REQUIRED main.dart CHANGE:

6. LIVE REFRESH BETWEEN QUICK-ADD AND THE TODO SCREEN
--------------------------------------------------------
- lib/services/todo_refresh_bus.dart (NEW)
    TodoRefreshBus.tick — a ValueNotifier<int> "something changed,
    please reload" signal. TodoRefreshBus.notify() bumps it.
- lib/widgets/quick_add_sheet.dart (MODIFIED)
    Calls TodoRefreshBus.notify() right after persisting a new task.
- lib/screens/todo_screen.dart (MODIFIED)
    Listens to TodoRefreshBus.tick in initState (calls _loadTasks),
    removes the listener in a new dispose() override. Fixes: adding a
    task via the FAB while already sitting on the TODO tab now shows
    up immediately instead of requiring a tab switch.
- lib/screens/calendar_screen.dart (MODIFIED, see section 7)
    Also listens to the same bus, so calendar markers update live too.

7. CALENDAR <-> TODO CONNECTION (real data, two-way)
---------------------------------------------------------
- lib/screens/calendar_screen.dart (REWRITTEN)
    Removed the old hardcoded _sampleEvents fake data. Now loads real
    tasks via AppDatabase.instance.getAllTodosWithSubtasks() +
    TodoTask.fromBundle (same call TodoScreen uses), groups them by
    due-date-only into _eventsByDate, and uses that both for:
      - the small dot marker on each day cell that has tasks due
      - the agenda list under the selected day (now real TodoTasks,
        rendered via a new _AgendaCard, not the old _AgendaItem)
    Constructor now requires `ValueChanged<DateTime> onViewDateInTodo`.
    When the selected day has tasks, a "View in TODO" TextButton
    appears that calls this callback.
- lib/screens/todo_screen.dart (MODIFIED)
    Added `DateTime? initialDateFilter` constructor param, `_dateFilter`
    state, `_isSameDate` helper. Filtering now combines priority AND
    date. A new _DateFilterBanner widget shows "Showing tasks due
    D/M/Y" with a dismiss (X) button above the priority chips whenever
    a date filter is active.
- lib/widgets/main_shell.dart (MODIFIED)
    Added `_todoDateFilter` field and a single `_openTodo({DateTime?
    dateFilter})` helper. Home's TODO card calls `_openTodo()` (no
    filter); Calendar's "View in TODO" calls `_openTodo(dateFilter:
    date)`. Keeps the filter from leaking between the two entry paths.

NOTE: Roadmap items have no due-date table yet, so they don't appear
on the calendar. Would need their own table (like Todos) to support
markers the same way, if/when Roadmap becomes real.

8. DATABASE — NO SCHEMA CHANGE NEEDED FOR TIME
---------------------------------------------------
Todos.dueDate is already a Drift DateTimeColumn, which stores a full
timestamp (date + time), not date-only. So adding the time picker
(section 5) required zero migration, no new column, no schemaVersion
bump — the existing column already had room for it.

9. NOTIFICATION / ALARM PERMISSIONS
----------------------------------------
- lib/services/permission_service.dart (NEW; originally named
  task_permissions_service.dart, renamed to be a general home for any
  future permission, not just task-related ones)
    class PermissionService:
      - requestNotificationPermission() -> bool
            Permission.notification.request().isGranted
            (POST_NOTIFICATIONS on Android 13+, standard prompt on iOS;
            no-op/true on older Android with no runtime permission)
      - requestExactAlarmPermission() -> bool
            Permission.scheduleExactAlarm.request().isGranted on
            Android 12+; always true on iOS/other platforms (no
            equivalent concept there)
      - isPermanentlyDenied(Permission) -> bool
      - openSettings() -> opens system app settings
- lib/widgets/todo_task_sheet.dart (MODIFIED)
    Notification and Alarm SwitchListTiles now call
    _onNotificationToggled / _onAlarmToggled instead of a plain
    setState. Turning ON requests the relevant permission first;
    granted -> switch turns on, denied -> SnackBar ("permission
    declined" or, if permanently denied, "permission is off in
    Settings" with an "Open Settings" action button). Turning OFF never
    requests anything.

REQUIRED DEPENDENCY:
    permission_handler: ^13.0.2   (latest as of this build; confirmed
                                   on pub.dev — note v12.0.0 bumped
                                   compileSdkVersion to 35 as a
                                   BREAKING CHANGE, so check
                                   android/app/build.gradle has
                                   compileSdk = 35 or higher)
